# وقتی نسخه خودکار گرفته نشد

اسکریپت `npm run update:versions` نسخه‌ها را از دو منبع می‌گیرد. برای بعضی
موجودیت‌ها هیچ‌کدام داده‌ای اگه ندارند. این مشکلی نیست — طراحی همین دیگه.

## اول ببینید چی شده

```bash
npm run update:versions
```

انتهای خروجی فهرست مواردی که نیاز به بررسی باشد را نشان می‌دهد. یک موجودیت خاص:

```bash
node scripts/update-versions.mjs --only=void --dry-run
```

## سه دلیلی که ممکنه پیش بیاد

**۱. `eolId` اشتباه است یا خالی است.**

`endoflife.date` برای هر محصول یک شناسه دارد و همیشه با نام توزیع یکی نیست.
فهرست کامل: <https://endoflife.date/api/all.json>

پیدایش کنید و در فایل موجودیت بگذارید:

```yaml
eolId: linuxmint
```

**۲. توزیع‌ی اگه اصلاً در `endoflife.date` نباشد.**

طبیعی‌ه — آن سایت فقط محصولات با چرخهٔ انتشار مشخص را پوشش می‌دهد.
توزیع‌های rolling مثل آرچ، وید و جنتو ذاتاً «نسخهٔ فعلی» ندارند.

**۳. ویکی‌داده مدخل دارد ولی نوعش تأیید نمی‌شود.**

اسکریپت عمداً سخت‌گیر است: مدخل باید `P31` درستی داشته باشد (توزیع گنو/لینوکس،
میزکار، یا پنجره‌گردان). این کار جلوی وصل شدن «Void» به یک فیلد را می‌گیرد.
اگر مطمئنید، شناسه را دستی بگذارید:

```yaml
wikidata: Q19928372
```

## سه راه‌حل پیش‌رو داریم، به ترتیب اولویت

### راه ۱ — سخت نگیرید، بیخیالش بشید (معمولاً بهترین)

فیلد را خالی بگذارید. در صفحه مربوطه می‌نویسد **«در حال بررسی»**. برای توزیع‌های
rolling این *دقیق‌تر* از هر عددی است، چون واقعاً نسخه‌ای وجود ندارد.

### راه ۲ — دستی وارد کنید، با تاریخ میلادی

```yaml
currentVersion: '3.20.1'
releasedAt: 2026-04-14
versionCheckedAt: 2026-08-07
```

`versionCheckedAt` را حتماً بنویسید. صفحه می‌گوید آخرین بررسی کی بوده، پس
خواننده می‌داند داده چقدر تازه است.

**هشدار:** اجرای بعدی اسکریپت این را رونویسی می‌کند — البته فقط اگر منبعی
پیدا کند. اگر منبعی نباشد، دست‌نوشتهٔ شما دست‌نخورده می‌ماند.

### راه ۳ — منبع سفارشی اضافه کنید

اگر پروژه‌ای API نسخه دارد (مثلاً GitHub Releases)، در
`scripts/update-versions.mjs` تابع `fetchEol` را الگو بگیرید و یک منبع
دیگر اضافه کنید.

برای پروژه‌های گیت‌هابی:

```
https://api.github.com/repos/<owner>/<repo>/releases/latest
```

## برای توزیع‌های rolling، اصلاً نگذارید

آرچ، وید، جنتو، تامبل‌وید، منجارو و گارودا نسخه ندارند. `releaseModel` را
روی `rolling` بگذارید و `currentVersion` را خالی. صفحه درست همان چیزی را
می‌گوید که واقعیت است.

## اگر همه‌چیز `fetch failed` داد

این یعنی هیچ درخواستی به مقصد نرسیده — مشکل از کد نیست، از شبکه شاهکار که داخل‌ش لذت می‌بریم، است.

هر دو منبع پشت CDN هستند و از داخل کشور اغلب مواقع در دسترس نیستند. اسکریپت حالا
خودش این حالت را تشخیص می‌دهد و راهنمایی می‌کند، ولی خلاصه‌اش:

**راه اول و بهترین — بگذارید CI انجامش دهد.**

ورک‌فلوی هفتگی روی رانرهای گیت‌هاب اجرا می‌شود(فعلا این است بعد ممکنه به داخل کشور نسبت به شرایط منتقل بشود) که این محدودیت را ندارند، و
نتیجه را در یک PR می‌گذارد:

```
Actions → "Update versions" → Run workflow
```

بعد PR را merge کنید. نسخه‌ها به‌روز می‌شوند بدون اینکه شما به شبکه نیاز
داشته باشید.

**راه دوم — پروکسی:**

```bash
HTTPS_PROXY=http://127.0.0.1:8080 npm run update:versions
```

**راه سوم — دستی.** بخش «راه ۲» بالاتر را ببینید.

برای دیدن جزئیات خطا:

```bash
npm run update:versions -- --verbose
```

حالا به‌جای `fetch failed` می‌گوید دقیقاً چه شد: `DNS lookup failed`،
`connection reset by peer`، `timed out after 15s` و مانند این.

## بررسی دستی اتصال

معمولاً شبکه است، نه کد:

```bash
curl -s https://endoflife.date/api/debian.json | head -c 200
curl -s "https://www.wikidata.org/w/api.php?action=wbsearchentities&search=Debian&language=en&format=json" | head -c 200
```

اگر این دو جواب ندادند، اسکریپت هم نمی‌تواند. در GitHub Actions این مشکل
پیش نمی‌آید، پس می‌توانید صبر کنید تا ورک‌فلو خودش انجامش دهد و
PR بسازد.
